# AllToDSH — чтобы новый чат в DeepSeek Harness помнил, где вы остановились

Несколько текстовых файлов в проекте. После них новый чат подхватывает работу по слову «продолжаем» — без пересказа контекста, без «объясни заново, что мы делали».

## Проблема

DeepSeek Harness хранит каждую сессию целиком: лог лежит в `%USERPROFILE%\.dsh\sessions\<путь-проекта>\session.v4.jsonl.zstd`, длинные треды автоматически сжимаются, а `goal` держит одну задачу через раунды. Всё это работает — но **внутри одной сессии и на одной машине**:

- новый чат не видит ни транскрипт, ни `goal` — открывается чистый лист;
- лог локальный и сжатый: не диффится, не ревьюится, на другую машину не поедет;
- в логе переписка, а нужны три строки: что решили, что сделано, что дальше.

AllToDSH добавляет недостающий слой: **маленький файл состояния в git**, который виден каждому новому чату.

## Как это работает

1. Работаете как обычно. Протокол велит агенту молча записывать в `TASK.md` решения, завершённые шаги и следующие шаги — по событию, а не по напоминанию.
2. Закрыли вкладку, открыли новый чат в той же папке, сказали **«продолжаем»**. Агент читает `TASK.md`, проверяет его и отвечает в 3–5 строк: «Цель: … / Сделано: … / Дальше: … — идём?». Говорите «идём» — работа продолжается с того же места.
3. Сменили машину — память в git, переехала вместе с кодом. Открыли, сказали «продолжаем».

## Что внутри

| Файл | Роль |
|---|---|
| `AGENTS.md` | Протокол. Harness загружает его сам в начале сессии: берёт `AGENTS.md` из корня проекта (корень — папка с `.git`). |
| `TASK.md` | Память: активная задача, решения, следующие шаги, реестр. |
| `templates/TASK.md` | Чистый шаблон для нового проекта. |
| `.agents/skills/resume/` | Скилл `/resume` — рукопожатие при продолжении. |
| `.agents/skills/checkpoint/` | Скилл `/checkpoint` — сохранить состояние. |
| `tools/memory-check.ps1` | Проверка: формат, свежесть по git, секреты. |
| `tools/install.ps1` | Установка в другой проект одной командой. |
| `.githooks/pre-commit` | Тихая проверка памяти перед коммитом. |

## Установка в свой проект

```powershell
git clone https://github.com/<вы>/AllToDSH C:\tools\AllToDSH
powershell -File C:\tools\AllToDSH\tools\install.ps1 -Target C:\work\мой-проект
```

Скрипт копирует файлы, инициализирует git (если его нет) и включает хуки. Существующие `AGENTS.md` и `TASK.md` **не перезаписывает** — скажет, что оставил как есть.

Вручную: скопировать `AGENTS.md`, `templates/TASK.md` (переименовать в `TASK.md`), `.agents/`, `tools/`, `.githooks/`, дописать строки из `.gitignore`. Затем:

```powershell
git config core.hooksPath .githooks
powershell -File tools/memory-check.ps1
```

Если в проекте уже есть свой `AGENTS.md` — не перетирайте: вставьте секцию протокола в него (Harness читает первый найденный `AGENTS.md` от корня к текущей папке).

## Команды

| Вы говорите | Что происходит |
|---|---|
| «продолжаем» / «продолжи» / «далее» / «где мы остановились» | Рукопожатие по `TASK.md`, ожидание «идём» |
| `/resume` | То же, явный вызов скилла |
| «сохрани контекст» / «на сегодня всё» | Запись состояния в `TASK.md` и коммит памяти |
| `/checkpoint` | То же, явный вызов скилла |
| «создай AllToDSH для этого проекта» | Установка в текущий проект |
| «убери AllToDSH» | Чекпоинт, затем удаление файлов протокола |

Слова-триггеры живут в `AGENTS.md` — этот файл загружается всегда, поэтому новые слова работают сразу. Меняйте под себя.

## Проверка

```powershell
powershell -File tools/memory-check.ps1
```

Смотрит: шапку (`Protocol`, `Обновлено`), статус задачи, длину секции (лимит 60 строк), наличие следующих шагов, существование путей из «Файлов для чтения», утечку секретов, отставание памяти от кода по git, незакоммиченные изменения без обновления памяти.

Код возврата 1 — есть ошибки (секреты, битый формат), 0 — всё в порядке. С `-Quiet` молчит, если ошибок нет: так его вызывает pre-commit.

Хук включён в этом репозитории и в проектах, куда вас поставил `install.ps1`:

```powershell
git config core.hooksPath .githooks
```

Он останавливает коммит только на ошибках. Обойти: `git commit --no-verify`.

## Чем это отличается от встроенного в Harness

| Возможность | Harness сам | AllToDSH |
|---|---|---|
| Продолжить тот же чат | да | — |
| Сжать длинный тред | да, автоматически | — |
| Автономные раунды долгой задачи | да, `goal` | — |
| Открыть **новый чат** и продолжить | нет | да |
| Другая машина или другой инструмент | нет | да, через git |
| Человекочитаемо и диффится в ревью | нет | да |
| Цена старта нового чата | весь лог | один файл, рукопожатие в 3–5 строк |

Это не замена, а дополнение: `goal` для длинных прогонов протокол использует, а не изобретает.

## Частые вопросы

**Это программа?** Нет. Текстовые файлы, один PowerShell-скрипт проверки и git-хук. Зависимостей нет.

**Агент будет молча писать в мой репозиторий?** Да, в `TASK.md` — по событиям (решение, готовый шаг, смена плана). Правила «Тишина» в протоколе запрещают отчитываться об этом и спрашивать разрешения.

**Секреты попадут в память?** Проверка ищет токены, ключи, пароли и учётные данные в URL. Найденное блокирует коммит.

**Модель забудет обновить память?** Тогда сработает pre-commit при коммите кода, а при resume видно расхождение дат: память от 26-го, код от 28-го. В рукопожатии это будет сказано одной строкой.

**Работаю в двух чатах одновременно?** Память принадлежит ветке. При слиянии конфликт в `TASK.md` решается по более позднему состоянию; если непонятно — переписать по факту из репозитория.

**А если память устарела или врёт?** Протокол велит доверять репозиторию, а не памяти, и назвать расхождение.

## Удаление

Скажите «убери AllToDSH» — агент сделает чекпоинт и удалит `TASK.md`, скиллы, `tools/`, `.githooks/` и секцию протокола из `AGENTS.md`. Вручную — то же самое; файл `AGENTS.md` целиком не удаляйте, там могут быть чужие правила.
