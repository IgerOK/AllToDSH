# AllToDSH — память проекта для DeepSeek Harness

Protocol: 1

Этот файл Harness загружает автоматически в начале каждой сессии: берёт `AGENTS.md` из корня проекта (корень — папка с `.git`) и подкладывает в контекст до первого ответа. Ниже — правила ведения памяти проекта. Сама память лежит в `TASK.md`.

Смысл один: **новый чат продолжает работу с того же места без пересказа контекста.**

## Файлы

| Файл | Роль |
|---|---|
| `AGENTS.md` | Этот протокол. Загружается автоматически. |
| `TASK.md` | Память: активная задача, решения, следующие шаги, реестр. В git. |
| `.notes/` | Черновики (L1). В `.gitignore`, никуда не переезжает. |
| `.agents/skills/resume/` | Скилл `/resume` — рукопожатие при продолжении. |
| `.agents/skills/checkpoint/` | Скилл `/checkpoint` — сохранить состояние. |
| `tools/memory-check.ps1` | Проверка: формат, свежесть, секреты. |
| `.githooks/pre-commit` | Тихая проверка памяти перед коммитом. |
| `DECISIONS-ARCHIVE.md` | Архив решений по дням. **Не** загружается автоматически: открывается при работе с подсистемой. Появляется, когда рабочих дней становится больше одного. |

## Бюджет `AGENTS.md` и суточный архив

`AGENTS.md` загружается целиком, поэтому у него есть бюджет: в DeepSeek Harness — **65 536 Б**. При превышении Harness обрезает хвост файла, и последние правила молча теряются (проверено 29.10.2026: файл 65 592 Б — под обрез попало только что добавленное решение).

Отсюда правило: **`AGENTS.md` — правила протокола + решения текущего рабочего дня.** Решение, последний раз изменённое в другой день, переезжает в `DECISIONS-ARCHIVE.md` — секцией по дате, от новых к старым. Архив не загружается автоматически; его открывают при работе с подсистемой, на которую ссылается пункт.

- Первая сессия нового дня: перенести из `AGENTS.md` все пункты прошлых дат в архив, оставить только текущий день.
- Секция архива: `## ГГГГ-ММ-ДД` и пункты в том же формате, что в `AGENTS.md`.
- Размер держать с запасом: `(Get-Item AGENTS.md).Length` ≤ 65 536 Б, лучше ≤ 32 КБ (день решений — обычно 10–20 КБ).
- Архив — часть памяти: коммитится вместе с `TASK.md` (`memory: …`), лежит в git, в `.gitignore` не попадает.
- `TASK.md` сжимается так же: больше 15 записей в «Реестре» — старые уходят в архив той же секцией по дате.
- Чужой проект со своим `AGENTS.md` — правило действует и там: секция протокола не должна раздувать файл, длинные решения — в архив.

## Триггеры

Продолжение: «продолжаем», «продолжи», «далее», «подними нить», «где мы остановились».
Сохранение: «сохрани контекст», «зафиксируй», «на сегодня всё», «закончим».
Установка: «создай AllToDSH для этого проекта», «поставь AllToDSH: <ссылка на репозиторий>».
Удаление: «убери AllToDSH».

Список живёт здесь, а не в `TASK.md`, потому что этот файл загружается всегда: новые слова работают сразу.

## Напоминание о времени при открытии диалога

Если сессия работает на Agnes/DeepSeek — напомни пользователю, что время скидки 50% на API DeepSeek указано для Минска (Беларусь): Пн–Пт 07:00–09:00 и 13:00–24:00, Сб–Вс круглосуточно. Для других регионов время нужно уточнять. В окна, не перечисленные выше, скидка не применяется.

## Правило чтения

В начале сессии прочитай `TASK.md`, если выполняется хотя бы одно:

- пользователь произнёс триггер продолжения;
- просьба продолжает работу над проектом («доделай», «вернёмся к», «исправь то, что начали»);
- задача явно про этот репозиторий.

Не читай ради вопросов, не связанных с работой (справка, разовый вопрос по одному файлу).

## Формат `TASK.md` — жёсткие лимиты

- Шапка: `Protocol: 1`, `Обновлено: ГГГГ-ММ-ДД`, `Рабочий язык`.
- Одна активная задача. Её секция — **не больше 60 строк**, весь файл — не больше 160.
- Скелет задачи: цель, как, текущее состояние, следующие 2–3 шага, решения, открытые вопросы, файлы для чтения, проверка.
- «Следующие шаги» — так, чтобы новый чат начал без истории: `файл — действие — как проверить`.
- Решения — в виде `что — почему`. Отброшенные варианты тоже, иначе их предложат снова.
- Пути и имена — дословно, в обратных кавычках.
- Секретов, токенов, паролей, персональных данных — нет. Никогда.
- Ссылок на чат и сессию — нет: чат умрёт, файл останется.
- Пересказа диалога — нет: память сжимает, а не дублирует.

## Статусы

`[PLANNED]` → `[IN PROGRESS]` → `[EXECUTED]` → `[RESOLVED]`, строго по порядку.

- **PLANNED** — задача записана до начала работы.
- **IN PROGRESS** — каждый завершённый шаг обновляет «Текущее состояние».
- **EXECUTED** — результат проверки записан; ждёт подтверждения пользователя.
- **RESOLVED** — только после явного «подтверждаю» или «ок». Активная задача снимается, в «Реестр» уходит одна строка.

## Когда писать — без вопросов и напоминаний

Пиши сразу, молча:

- принято решение, которое дорого переиграть → «Решения»;
- шаг завершён и проверен → «Текущее состояние» и «Следующие шаги»;
- план изменился → «Как» и «Следующие шаги»;
- вопрос закрыт → убрать из «Открытых вопросов»;
- задача завершена → `[EXECUTED]`, записать проверку;
- пользователь сказал триггер сохранения → полный чекпоинт;
- собираешься коммитить код → сначала обнови память, иначе pre-commit остановит.

Не пиши, если потерять нечего: задача на один шаг, вопрос-справка, эксперимент, который тут же откатили.

## Свежесть

`Обновлено` в шапке — дата последнего содержательного изменения памяти. Если код менялся позже, память устарела. Проверка одной командой:

```
powershell -File tools/memory-check.ps1
```

Перед коммитом её запускает `.githooks/pre-commit` (включается через `git config core.hooksPath .githooks`).

## Resume — новый чат

1. Прочитать `TASK.md`.
2. Проверить: активная задача есть, цель заполнена, шаги конкретны, секция не больше 60 строк, файлы из «Файлов для чтения» существуют, секретов нет, дата не старше кода. Если есть `tools/memory-check.ps1` — запустить.
3. Ответить в 3–5 строк: `Цель: … / Сделано: … / Дальше: … — идём?` и ждать «идём».
4. После «идём» — строго с первого следующего шага.

Новому чату запрещено: переосмыслять «Решения», заново исследовать уже описанное, начинать новые подзадачи при активной задаче, переписывать память по своему вкусу.

Если память устарела или противоречит репозиторию — скажи это одной строкой в рукопожатии и опирайся на факты из репозитория, а не на память.

## Checkpoint — «сохрани контекст»

1. Собрать: что сделано и проверено, что в работе (файл и место), что дальше.
2. Записать по скелету, обновить `Обновлено`.
3. Прогнать `tools/memory-check.ps1`.
4. Коммит: `memory: <задача> — <состояние>`.
5. Ответить одной строкой: что сохранено.

## Тишина

- Не сообщай «я обновил TASK.md» — это служебное действие.
- Не спрашивай разрешения на запись в `TASK.md`.
- Рукопожатие — максимум 5 строк, без пересказа истории.
- Чекпоинт — одна строка отчёта.
- Проблему памяти (устарела, битая, противоречит коду) называй прямо и коротко: это не шум, это данные.

## Git

- Память и код коммитятся вместе: код без обновления памяти — незавершённая работа.
- Коммиты памяти: `memory: …`. Код: обычные сообщения.
- Память принадлежит ветке. При merge конфликт в `TASK.md` решается в пользу более позднего состояния; если непонятно — переписать по факту из репозитория.
- Remote и push — только по просьбе пользователя.

## Если память сломана

Не выдумывай. Сообщи: `TASK.md не прошёл проверку: <что именно>`. Предложи восстановить через `git checkout -- TASK.md` или пересобрать по текущему состоянию репозитория. Действуй после выбора.

## Новый проект

Триггеры: «создай AllToDSH для этого проекта», «поставь AllToDSH сюда» — в том числе со ссылкой на репозиторий.

1. Источник выбери по порядку:
   - дана ссылка на репозиторий → `git clone <ссылка> <временная папка>`;
   - git недоступен → скачай архив: `Invoke-WebRequest <ссылка>/archive/refs/heads/main.zip -OutFile <zip>` и распакуй `Expand-Archive`;
   - указан локальный путь → используй его;
   - ничего не указано → `https://github.com/IgerOK/AllToDSH`.
2. Установи: `powershell -File <источник>\tools\install.ps1 -Target <корень текущего проекта>`.
3. Заполни `TASK.md`: цель из задачи пользователя, «Текущее состояние», 2–3 следующих шага, проверка.
4. Если проект под git — первый коммит `AllToDSH init`; включи `git config core.hooksPath .githooks` (установщик делает это сам).
5. Удали временную копию источника. Ответ — одной строкой: `AllToDSH инициализирован: <путь>`.

## Длинные задачи

Если работа не влезает в один заход — заведи goal (`create_goal`) с целью из `TASK.md`: Harness продолжит раунды сам. После открытия сессии активный goal разоружён — `update_goal resume`. В новый чат goal не переносится: его восстанавливают из `TASK.md`.

## Язык

Рабочий язык — `Рабочий язык` в шапке `TASK.md` (по умолчанию русский). Переключайся, только если пользователь сам перешёл.

## Удаление

«Убери AllToDSH»: сначала чекпоинт, затем удалить `TASK.md`, `.agents/skills/resume`, `.agents/skills/checkpoint`, `tools/`, `.githooks/` и секцию протокола из `AGENTS.md`. Файл может содержать чужие правила — целиком его не удаляй.

## Приоритет

Глобальные `~/.dsh/AGENTS.md` и `~/.agents/AGENTS.md` задают общее поведение. Этот файл задаёт только память проекта. В конфликтах по памяти и статусам приоритет у этого файла.
